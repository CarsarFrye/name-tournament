# 四十八个名字 · 以名会友

基于用户提供的48个名字名单构建的本地网页对战游戏。支持手动出牌、自动演赛、随机分组、小组循环赛与双败淘汰赛。每场固定进行三局，双方逐局得分累加决定胜者。手动模式自动完成 NPC 对局，只停在玩家需要出牌的局；自动演赛优先播放玩家的具体对局。玩家淘汰后赛程仍继续推演，并在横向赛程树中展示完整结果。

## 本地运行

要求 Node.js 22.12 或更新版本。当前开发机已安装 Node.js 26。

```powershell
npm install
npm run dev
```

打开终端显示的本地地址即可试玩。赛程只保存在当前浏览器的 `localStorage` 中。

## 检查与构建

```powershell
npm run check:rules
npm run build
npm run preview
```

## 发布到 GitHub Pages

项目已包含 GitHub Actions 工作流。将此目录推送到 GitHub 上名为 `name-tournament` 的公开仓库，进入仓库的 **Settings → Pages** 并将来源设为 **GitHub Actions**。之后推送到 `main` 分支会自动构建和发布。

GitHub Pages 的站点公开可见；仓库只应包含这个游戏项目，不要把工作目录中的其他文件提交进去。

## 评分说明

四维评分由随项目打包的本地字符资料和固定公式生成，不请求 AI、服务器或在线数据库，也不会上传名字。汉字读音、笔画、释义和词频来自 Unicode 官方 Unihan 数据；生成后的精简资料覆盖约 4.5 万个汉字并随网页一起下载，因此离线也能评分。来源说明和许可见 `public/data/UNIHAN-SOURCE.md`。

评分仍是启发式估算：当前数据约有 44,355 个汉字的普通话读音、45,496 个汉字的笔画资料、23,310 个英文释义，但《汉语频率词典》词频仅覆盖 3,799 个字，其余字的辨识度频率值采用中性回退。读音使用资料默认读音，多音字可能不符合具体名字里的读法；字符词频不等于姓名流行度或真实人口重名率；意涵分按释义中的通用褒贬词估算，不能理解姓名组合、出处、性别适配或时代气质。缺少普通话读音的字符会使用中性值，并在页面提示。评分不再参考本届 48 人名单的重复字，因此不会因为名字与 NPC 共用汉字而加减分。

评分不再把四维结果拉回相似的固定分布。音韵会看声调跨度与转折、声母/韵母重复；字形会看平均笔画、笔画差异、相邻字落差；意涵使用 Unihan 释义中的褒贬线索；辨识结合可用词频与音节、声韵组合。不同名字可以有不同强项与弱点。资料不足时仍会使用中性回退，因此这套评分是可解释的本地启发式，不是对姓名优劣的客观判定。

战斗基础分使用出战属性相对该名字自身四维均值和离散程度的强弱，并设上限，避免四项整体偏高的名字天然压制其他选手。本命和弱点会影响基础分；克制关系将基础分乘以 1.18 或 0.88，场景属性另加 0.75 分。NPC 按策略倾向出牌，同时根据场景与固定随机种子进行探索；每位选手每局另有 -0.6、-0.3、0、+0.3、+0.6 五档临场波动。双方每场各属性不能重复，完成三局后比较累计得分；总积分持平时比较小局领先数，再以赛事种子裁决。运行 `node --experimental-strip-types scripts/balance-report.ts 100 500` 可复查 12 个自定义名字与 500 个基准赛季的晋级率、平均积分差和胜场分布。
